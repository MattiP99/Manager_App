# Note Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tab Note con sezioni (Info importanti / Info secondarie / Password, create automaticamente alla creazione dell'household, più sezioni `custom` aggiungibili dall'utente), ciascuna con le proprie note. La sezione Password cifra il contenuto delle note lato client (AES-256-GCM) con una chiave derivata da una passphrase condivisa a livello di household, mai inviata al server.

**Architecture:** Due nuove tabelle household-scoped (`note_sections`, `notes`) con lo stesso pattern RLS già stabilito. La creazione delle 3 sezioni di base viene spostata nel database stesso, estendendo la funzione `create_household` già esistente (nessuna nuova RPC). La cifratura è interamente client-side: `expo-crypto` fornisce AES-256-GCM nativo (non serve alcuna libreria di cifratura in più), ma **non fornisce derivazione di chiave da password** — per quello si aggiunge `@noble/hashes` (PBKDF2-HMAC-SHA256, pura libreria JS, zero dipendenze, nessun codice nativo). La chiave derivata (non la passphrase) viene cachata localmente con `expo-secure-store` su nativo e un fallback `localStorage` su web (stesso pattern già usato in `src/lib/supabase.ts` per la sessione Supabase), per sopravvivere ai riavvii dell'app.

**Tech Stack:** Stesso stack dei blocchi precedenti — Expo Router, TypeScript, `@supabase/supabase-js` con tipi generati, TanStack Query, Jest. Nuove dipendenze: `expo-crypto`, `expo-secure-store` (SDK 57, via `npx expo install`), `@noble/hashes` (via `npm install`, pura libreria JS).

**Spec:** `docs/superpowers/specs/2026-09-17-family-manager-app-design.md` (sezione 4.5 per lo schema, sezione 5 per la posizione del tab `note/`; nota: la spec menziona "PBKDF2 via `expo-crypto`" — **verificato contro la documentazione ufficiale SDK 57 che questo è impreciso**: `expo-crypto` non espone alcuna funzione di key-derivation, solo digest/random/AES — vedi Global Constraints sotto per i fatti verificati che sostituiscono quell'assunzione)

**Precede questo piano (già completato):** tutti i blocchi 1-5. Questo piano riusa `is_household_member(household_id)` da `0002_fix_household_members_rls_recursion.sql` e la funzione `create_household` da `0001_households.sql` (che estende, non sostituisce concettualmente).

**Decisioni di scope confermate con l'utente (brainstorming):**
- La passphrase della sezione Password è **condivisa a livello di household** (non personale per utente): chiunque la conosce può leggere/scrivere le note su qualsiasi dispositivo. Il salt (non segreto) e un piccolo valore "canary" cifrato (per verificare che la passphrase inserita sia corretta anche prima che esista una nota reale) vivono nel database, nella riga della sezione Password stessa — mai la passphrase, mai la chiave derivata.
- Sblocco **persistente tra riavvii**: dopo il primo inserimento corretto della passphrase su un dispositivo, la chiave derivata (non la passphrase) resta salvata localmente (SecureStore su nativo, `localStorage` su web) e non va reinserita finché l'utente non disinstalla l'app / pulisce i dati del browser.
- **Fuori scope, esplicitamente**: nessun cambio/rotazione della passphrase (coerente con "se si perde, le note sono irrecuperabili" già dichiarato dalla spec — ruotare richiederebbe ri-cifrare tutte le note esistenti); nessun riordino drag-and-drop delle sezioni custom (`sort_order` assegnato in ordine di creazione, mai modificato); nessun bottone "blocca ora" manuale (contraddirebbe la scelta dello sblocco persistente).

## Global Constraints

- Nessuna nuova RPC: `note_sections`/`notes` usano RLS via `is_household_member(household_id)` (funzione già esistente), con un'unica policy `for all` per tabella — stesso pattern di tutte le tabelle precedenti. L'unica funzione toccata è `create_household`, estesa con `create or replace function` per inserire le 3 sezioni di base.
- **Preservare l'hardening di `search_path`:** `create_household` ha già `search_path = public, pg_temp` impostato da `0003_harden_search_path.sql` tramite un `alter function` separato — quel `alter function` non tocca più nulla dopo questo piano, perché questo piano **ridefinisce l'intero corpo** della funzione con `create or replace function`. La nuova definizione DEVE dichiarare esplicitamente `set search_path = public, pg_temp` nel proprio corpo (non `set search_path = public` da solo, che è quello che c'era nella versione originale di `0001` prima dell'hardening) — altrimenti questo piano silenziosamente disfa un fix di sicurezza già fatto. Vedi il codice esatto nel Task 1.
- **Vincolo CHECK su `notes`:** `check ((content is not null) <> (content_encrypted is not null))` — esattamente uno dei due campi deve essere valorizzato, mai entrambi, mai nessuno. Stesso principio dei CHECK incrociati già usati per `expenses.francesca_activity`.
- **API di cifratura verificate contro la documentazione ufficiale SDK 57** (`https://docs.expo.dev/versions/v57.0.0/sdk/crypto/` e `.../sdk/securestore/`, controllate esplicitamente per questo piano perché la spec assumeva un'API che non esiste in questa versione) — questi fatti sono la base di verità per il Task 4, non riderivarli né assumerne altri:
  - `aesEncryptAsync(plaintext, key, options?)` e `aesDecryptAsync(sealedData, key, options?)` (import diretto da `expo-crypto`, come mostrato nell'esempio ufficiale della documentazione — non `import * as Crypto`) fanno AES-256-GCM nativo. `plaintext` accetta `Uint8Array` direttamente (non serve base64 se non è una stringa) — usare SEMPRE `Uint8Array` per il testo in chiaro (mai una stringa passata direttamente), per evitare completamente il problema "`btoa` non gestisce correttamente caratteri accentati italiani come è/à/ì/ò/ù" (una stringa passata a queste funzioni DEVE essere già base64, e non c'è modo sicuro/universale di produrre quel base64 da testo Unicode arbitrario con le API globali disponibili su nativo — passare `Uint8Array` bypassa il problema del tutto).
  - `AESEncryptionKey.import(bytes: Uint8Array)` crea una chiave da materiale di chiave proprio (es. l'output di PBKDF2) — non serve `.generate()` (che crea una chiave casuale, non da password).
  - Il risultato di `aesEncryptAsync` è un `AESSealedData`; `await sealed.combined('base64')` restituisce una stringa base64 pronta per il database (IV+ciphertext+tag combinati in un unico blob) — **questo è l'UNICO punto in cui base64 è sicuro da usare**, perché opera su byte grezzi (il ciphertext), non su testo Unicode.
  - Per decifrare: `AESSealedData.fromCombined(base64String)` ricostruisce il sealed data dalla stringa salvata; `await aesDecryptAsync(sealed, key, { output: 'bytes' })` restituisce un `Uint8Array` (mai chiedere `output: 'base64'` per poi fare `atob` — stesso problema Unicode di sopra).
  - `getRandomBytesAsync(n)` genera n byte casuali sicuri — usato per il salt.
  - `expo-crypto` **non ha nessuna funzione di key-derivation da password** (niente PBKDF2/scrypt/argon2) — da qui la dipendenza `@noble/hashes`.
  - `expo-secure-store` **non funziona su web** (solo Android/iOS/tvOS) — serve lo stesso pattern `Platform.OS === 'web' ? ... : ...` già usato in `src/lib/supabase.ts` per la sessione Supabase.
- **Confine testo↔byte:** usare `TextEncoder`/`TextDecoder` (API web standard, disponibili sia in Node — quindi testabili — sia nel runtime Hermes di React Native da diverse versioni) per convertire tra stringa JS e `Uint8Array` UTF-8. Mai `btoa`/`atob` in questo piano.
- **Salt e chiave in byte, mai passati per testo:** per salvare byte grezzi (salt, chiave cachata) come stringa, usare `bytesToHex`/`hexToBytes` da `@noble/hashes/utils` (già una dipendenza di questo blocco) — mai un encoder base64 scritto a mano, mai `btoa`.
- **Limite di test noto e accettato esplicitamente:** il codice che chiama `expo-crypto`/`expo-secure-store` (Task 4) non può essere eseguito sotto `jest-expo/node` (nessun bridge nativo in Node) — non è un gap da colmare in questo piano, è lo stesso tipo di limite già accettato per l'assenza di browser headless in questo progetto. Verifica per il Task 4: lettura attenta del codice contro i fatti API verificati sopra, non un test automatico. **Raccomandazione esplicita per l'utente dopo questo blocco:** questa è l'unica parte dell'intero progetto che non può essere verificata dalla sola pipeline AI — testare manualmente il flusso reale (impostare una passphrase, aggiungere una nota cifrata, riavviare l'app, verificare che resti sbloccata, provare una passphrase sbagliata) su `npx expo start --web` o un dispositivo reale prima di considerare il blocco definitivamente concluso.
- Dopo aver installato le nuove dipendenze npm pure (`@noble/hashes`), leggere i tipi effettivamente installati (`node_modules/@noble/hashes/pbkdf2.d.ts` e `.../utils.d.ts`) prima di scrivere il wrapper — la firma esatta mostrata in questo piano è quella nota al momento della scrittura, ma va confermata contro la versione realmente risolta da npm, stesso principio del "verificare la documentazione prima di scrivere codice" applicato qui a una libreria non-Expo.

- [ ] **Step 1: Scrivi la migrazione `supabase/migrations/0008_notes.sql`**

```sql
-- Note: sezioni (info/password/custom) + note vere e proprie. Le sezioni
-- Password conservano solo materiale non segreto (salt, canary cifrato) —
-- la passphrase stessa non tocca mai il server, la chiave si deriva e si
-- cifra/decifra interamente sul client (vedi Task 3/4).

create table note_sections (
  id uuid primary key default gen_random_uuid(),
  household_id uuid not null references households(id) on delete cascade,
  title text not null,
  type text not null check (type in ('info', 'password', 'custom')),
  sort_order int not null default 0,
  -- Solo per la sezione 'password': salt (esadecimale) usato per derivare
  -- la chiave dalla passphrase, e un piccolo valore noto cifrato con quella
  -- chiave (per verificare che una passphrase inserita sia corretta anche
  -- prima che esista una nota reale da provare a decifrare). Nessuno dei
  -- due è materiale segreto: senza la passphrase non permettono di
  -- decifrare nulla.
  encryption_salt text,
  encryption_canary text,
  created_at timestamptz not null default now()
);

create table notes (
  id uuid primary key default gen_random_uuid(),
  section_id uuid not null references note_sections(id) on delete cascade,
  household_id uuid not null references households(id) on delete cascade,
  title text not null,
  -- Esattamente uno dei due è valorizzato: content per sezioni info/custom
  -- (testo in chiaro), content_encrypted per la sezione password (base64
  -- del blob combinato IV+ciphertext+tag di aesEncryptAsync).
  content text,
  content_encrypted text,
  created_at timestamptz not null default now(),
  check ((content is not null) <> (content_encrypted is not null))
);

alter table note_sections enable row level security;
alter table notes enable row level security;

create policy "household members manage note_sections" on note_sections
  for all using (is_household_member(household_id)) with check (is_household_member(household_id));

create policy "household members manage notes" on notes
  for all using (is_household_member(household_id)) with check (is_household_member(household_id));

-- Estende create_household (0001_households.sql) per creare automaticamente
-- le 3 sezioni di base alla creazione di un household. search_path hardening
-- di 0003_harden_search_path.sql dichiarato esplicitamente qui (non solo
-- "public" come nella versione originale di 0001) perché questo
-- `create or replace` ridefinisce l'intero corpo della funzione.
create or replace function create_household(p_name text)
returns households
language plpgsql
security definer
set search_path = public, pg_temp
as $$
declare
  new_household households;
begin
  if auth.uid() is null then
    raise exception 'Not authenticated';
  end if;
  if p_name is null or length(trim(p_name)) = 0 then
    raise exception 'Household name is required';
  end if;

  insert into households (name, invite_code)
  values (trim(p_name), generate_invite_code())
  returning * into new_household;

  insert into household_members (household_id, user_id)
  values (new_household.id, auth.uid());

  insert into note_sections (household_id, title, type, sort_order) values
    (new_household.id, 'Info importanti', 'info', 0),
    (new_household.id, 'Info secondarie', 'info', 1),
    (new_household.id, 'Password', 'password', 2);

  return new_household;
end;
$$;
```

import { pbkdf2 } from '@noble/hashes/pbkdf2';
import { sha256 } from '@noble/hashes/sha256';

// 210.000 iterazioni: raccomandazione OWASP 2023 per PBKDF2-HMAC-SHA256.
const PBKDF2_ITERATIONS = 210_000;
const KEY_LENGTH_BYTES = 32; // AES-256

/** Deriva una chiave AES-256 (32 byte) da una passphrase e un salt, via PBKDF2-HMAC-SHA256. Deterministica: stessa passphrase + stesso salt -> stessa chiave, sempre. */
export function deriveKey(passphrase: string, salt: Uint8Array): Uint8Array {
  const passphraseBytes = new TextEncoder().encode(passphrase);
  return pbkdf2(sha256, passphraseBytes, salt, { c: PBKDF2_ITERATIONS, dkLen: KEY_LENGTH_BYTES });
}

import { AESEncryptionKey, AESSealedData, aesDecryptAsync, aesEncryptAsync, getRandomBytesAsync } from 'expo-crypto';
import { bytesToHex, hexToBytes } from '@noble/hashes/utils';
import { deriveKey } from './pbkdf2';
import { decodeUtf8, encodeUtf8 } from './textCodec';

const CANARY_PLAINTEXT = 'note-app-verify';
const SALT_BYTES = 16;

/** Cifra un testo con AES-256-GCM, restituendo una stringa base64 (IV+ciphertext+tag combinati) pronta per il database. */
export async function encryptText(plaintext: string, keyBytes: Uint8Array): Promise<string> {
  const key = await AESEncryptionKey.import(keyBytes);
  const sealed = await aesEncryptAsync(encodeUtf8(plaintext), key);
  const combined = await sealed.combined('base64');
  return combined as string;
}

/** Decifra una stringa base64 (prodotta da encryptText) tornando al testo in chiaro originale. Lancia un'eccezione se la chiave è sbagliata (il tag di autenticazione GCM non verifica). */
export async function decryptText(combinedBase64: string, keyBytes: Uint8Array): Promise<string> {
  const key = await AESEncryptionKey.import(keyBytes);
  const sealed = AESSealedData.fromCombined(combinedBase64);
  const bytes = await aesDecryptAsync(sealed, key, { output: 'bytes' });
  return decodeUtf8(bytes as Uint8Array);
}

/** Prima configurazione della sezione Password: genera un salt casuale, deriva la chiave dalla passphrase scelta dall'utente, e cifra un valore noto (canary) con quella chiave per poterla verificare in futuro. Il chiamante salva saltHex/canaryBase64 su note_sections e keyBytes localmente (vedi secureKeyStore.ts). */
export async function setupPasswordSection(
  passphrase: string
): Promise<{ saltHex: string; canaryBase64: string; keyBytes: Uint8Array }> {
  const saltBytes = await getRandomBytesAsync(SALT_BYTES);
  const keyBytes = deriveKey(passphrase, saltBytes);
  const canaryBase64 = await encryptText(CANARY_PLAINTEXT, keyBytes);
  return { saltHex: bytesToHex(saltBytes), canaryBase64, keyBytes };
}

/** Sblocco della sezione Password (già configurata): deriva la chiave dalla passphrase inserita usando il salt salvato, poi la verifica decifrando il canary. Restituisce la chiave se la passphrase è corretta, null altrimenti (mai lanciare un'eccezione per una passphrase sbagliata — è un caso atteso, non un errore). */
export async function unlockPasswordSection(
  passphrase: string,
  saltHex: string,
  canaryBase64: string
): Promise<Uint8Array | null> {
  const saltBytes = hexToBytes(saltHex);
  const keyBytes = deriveKey(passphrase, saltBytes);
  try {
    const decoded = await decryptText(canaryBase64, keyBytes);
    return decoded === CANARY_PLAINTEXT ? keyBytes : null;
  } catch {
    return null;
  }
}

import { Platform } from 'react-native';
import * as SecureStore from 'expo-secure-store';

const STORAGE_KEY = 'notes_encryption_key';

// expo-secure-store non funziona su web (solo Android/iOS/tvOS) — stesso
// pattern Platform.OS === 'web' già usato in src/lib/supabase.ts per la
// sessione Supabase, con lo stesso guard SSR (typeof window === 'undefined').
async function webGet(): Promise<string | null> {
  return typeof window === 'undefined' ? null : window.localStorage.getItem(STORAGE_KEY);
}
async function webSet(value: string): Promise<void> {
  if (typeof window !== 'undefined') window.localStorage.setItem(STORAGE_KEY, value);
}
async function webRemove(): Promise<void> {
  if (typeof window !== 'undefined') window.localStorage.removeItem(STORAGE_KEY);
}

/** Legge la chiave AES cachata localmente (se presente — null se la sezione Password non è mai stata sbloccata su questo dispositivo). */
export async function loadStoredKey(): Promise<Uint8Array | null> {
  const hex = Platform.OS === 'web' ? await webGet() : await SecureStore.getItemAsync(STORAGE_KEY);
  return hex ? hexToBytes(hex) : null;
}

      const setup = await setupPasswordSection(passphrase);
      await configurePasswordSection.mutateAsync({
        sectionId: section.id,
        saltHex: setup.saltHex,
        canaryBase64: setup.canaryBase64,
      });
      await storeKey(setup.keyBytes);
      setKey(setup.keyBytes);
      return;
    }

    const unlockedKey = await unlockPasswordSection(passphrase, section.encryption_salt, section.encryption_canary);
    if (!unlockedKey) {
      setUnlockError('Passphrase errata.');
      return;
    }
    await storeKey(unlockedKey);
    setKey(unlockedKey);
  };

  const locked = isPasswordSection && checkedStoredKey && !key;

  return (
    <View style={styles.container}>
      <Text style={styles.title}>{section.title}</Text>

      {locked && (
        <View style={styles.unlockBox}>
          <Text style={styles.unlockLabel}>
            {section.encryption_salt
              ? 'Inserisci la passphrase per sbloccare questa sezione'
              : 'Imposta una passphrase per proteggere questa sezione (condivisa con tutta la famiglia — se si perde, le note non sono più recuperabili)'}
          </Text>
          <TextInput
            style={styles.input}
            placeholder="Passphrase"
            secureTextEntry
            value={passphrase}
            onChangeText={setPassphrase}
          />
          {unlockError && <Text style={styles.error}>{unlockError}</Text>}
          <Pressable style={styles.button} onPress={handleSubmitPassphrase}>
            <Text style={styles.buttonText}>{section.encryption_salt ? 'Sblocca' : 'Imposta passphrase'}</Text>
          </Pressable>
        </View>
      )}

      {(!isPasswordSection || key) && (
        <>
          <Pressable
            style={styles.addButton}
            onPress={() => router.push({ pathname: '/add-note', params: { sectionId: section.id } })}
          >
            <Text style={styles.addButtonText}>+ Nota</Text>
          </Pressable>
          <FlatList
            style={{ flex: 1 }}
            data={notes ?? []}
            keyExtractor={(n) => n.id}
            renderItem={({ item }) => (
              <Pressable style={styles.row} onPress={() => router.push({ pathname: '/edit-note', params: { id: item.id } })}>
                <Text style={styles.rowTitle}>{item.title}</Text>
                <Text numberOfLines={1}>{isPasswordSection ? decryptedContent[item.id] ?? '...' : item.content}</Text>
              </Pressable>
            )}
            ListEmptyComponent={<Text>Nessuna nota ancora.</Text>}
          />
        </>
      )}

      <Pressable onPress={() => router.back()}>
        <Text style={styles.cancel}>Indietro</Text>
      </Pressable>
    </View>
  );
}

import { useNoteSections } from '../features/notes/useNoteSections';
import { useDeleteNote, useNotesBySection, useUpdateNote } from '../features/notes/useNotes';
import { decryptText, encryptText } from '../features/notes/crypto/aesNotes';
import { loadStoredKey } from '../features/notes/crypto/secureKeyStore';

export default function EditNoteScreen() {
  const { id, sectionId } = useLocalSearchParams<{ id: string; sectionId: string }>();
  const { data: sections } = useNoteSections();
  const section = sections?.find((s) => s.id === sectionId);
  const { data: notes } = useNotesBySection(sectionId);
  const note = notes?.find((n) => n.id === id);
  const updateNote = useUpdateNote();
  const deleteNote = useDeleteNote();

  const isPasswordSection = section?.type === 'password';

  const [title, setTitle] = useState('');
  const [content, setContent] = useState('');
  const [decryptError, setDecryptError] = useState(false);
  const [hydrated, setHydrated] = useState(false);

  useEffect(() => {
    if (!note || !section) return;
    setTitle(note.title);
    setDecryptError(false);

    if (!isPasswordSection) {
      setContent(note.content ?? '');
      setHydrated(true);
      return;
    }

    if (!note.content_encrypted) {
      setHydrated(true);
      return;
    }
    loadStoredKey().then(async (key) => {
      if (!key) {
        setDecryptError(true);
        setHydrated(true);
        return;
      }
      try {
        const plain = await decryptText(note.content_encrypted!, key);
        setContent(plain);
      } catch {
        setDecryptError(true);
      }
      setHydrated(true);
    });

  if (!sections || !notes) return <Text style={styles.padded}>Caricamento...</Text>;

    if (!title.trim() || !content.trim()) return;

    if (isPasswordSection) {
      const key = await loadStoredKey();
      if (!key) return;
      const contentEncrypted = await encryptText(content.trim(), key);
      updateNote.mutate(
        { id: note.id, sectionId: section.id, title: title.trim(), contentEncrypted },
        { onSuccess: () => router.back() }
      );
      return;
    }

    updateNote.mutate(
      { id: note.id, sectionId: section.id, title: title.trim(), content: content.trim() },
      { onSuccess: () => router.back() }
    );
  };

  const handleDelete = () => {
    deleteNote.mutate({ id: note.id, sectionId: section.id }, { onSuccess: () => router.back() });
  };

  return (
    <ScrollView contentContainerStyle={styles.container}>
      <Text style={styles.title}>Modifica nota — {section.title}</Text>
      {decryptError && <Text style={styles.error}>Impossibile decifrare questa nota (chiave mancante o passphrase diversa da quella usata per salvarla).</Text>}

      <TextInput style={styles.input} placeholder="Titolo" value={title} onChangeText={setTitle} />
      <TextInput
        style={[styles.input, styles.multiline]}
        placeholder="Contenuto"
        value={content}
        onChangeText={setContent}
        multiline
      />

      {updateNote.isError && <Text style={styles.error}>{(updateNote.error as Error).message}</Text>}
      <Pressable style={styles.button} onPress={handleSave} disabled={updateNote.isPending}>
        <Text style={styles.buttonText}>Salva</Text>
      </Pressable>
      <Pressable style={styles.deleteButton} onPress={handleDelete} disabled={deleteNote.isPending}>
        <Text style={styles.deleteButtonText}>Elimina nota</Text>
      </Pressable>
      <Pressable onPress={() => router.back()}>
        <Text style={styles.cancel}>Annulla</Text>
      </Pressable>
    </ScrollView>
  );
}
